What does Azure API Management do between an AI application and its models?

The application calls one gateway endpoint. Azure API Management (APIM) checks the caller, applies the policies you configure and forwards eligible requests to a model deployment. Try a scenario to see where the request goes and what comes back.

Architecture and policy notes

This lab models XML policies on an Azure API Management instance. Microsoft also documents a separately configured AI Gateway preview. Check policy, tier, gateway and model API support before deploying.

Identity on both hops

Use validate-azure-ad-token to validate the caller’s Microsoft Entra token. The demo uses a separate authorization check that returns 403 for a valid caller without permission. Claim validation inside the same token policy uses its configured failure status, which defaults to 401. Grant APIM’s managed identity the appropriate role on the model backend.

Rate and quota are different

llm-token-limit can apply a per-key tokens-per-minute limit (429) and a fixed UTC quota window (403). This demo checks an already exhausted daily budget first. Live usage can come from response token counts or estimates. Streaming and concurrent requests affect precision, and counters are tracked independently per gateway.

Route by configuration

set-backend-service targets a backend or pool. Use choose for explicit model or operation rules. The two deployments here serve the same chat API contract. With the primary circuit already open, the configured priority pool can select the secondary.

Cache within the right boundary

llm-semantic-cache-lookup compares embeddings against entries in a configured external cache such as Azure Managed Redis. llm-semantic-cache-store stores eligible responses. Set a similarity threshold, expiry and vary-by partition. Keep tenant, permission and model boundaries intact. The demo places lookup after token checks.

Separate gateway and backend errors

A backend can return its own 429 or 503. A circuit opens according to its configured rules. To retry the same request after a failure, configure a bounded retry policy and consider replay safety. Verify what happens before and after a streaming response starts.

Plan what to measure

Configure diagnostics for status, latency and request correlation. llm-emit-token-metric can emit token usage to Application Insights. Choose low-cardinality metric dimensions and limit prompt and completion logging. Provider billing and capacity limits apply independently.
