    Notes
    • Global and regional ingress. Front Door Premium is the public endpoint. Its origin connection uses approved Private Link to an Application Gateway v2 frontend in UK South. Private APIM and AKS are deployed in the same region. Application Gateway routes /api to the private API Management gateway; the lab models routing only at this hop. A separately configured regional WAF could make its own decision. Align host names, TLS certificates, private DNS and health probes across the hops.
    • Edge inspection. In this WAF policy, custom Block runs at priority 10 and custom Allow at 20, before the managed Default Rule Set. In Prevention mode a matching Allow ends inspection by this WAF, including managed rules. Give exceptions a narrow scope. Detection mode monitors and logs matches with diagnostics enabled and forwards the request. The managed input represents an anomaly score at or above the block threshold, with the anomaly action configured to Block.
    • API access. This APIM example uses validate-azure-ad-token with its default 401 on failure. A separate role condition uses return-response configured for 403. rate-limit-by-key uses a verified client identity and returns 429 when its counter is over limit. The demo skips the per-client counter if token validation is off and rejects requests if a role is required without a verified identity.
    • Private backend. This example uses Premium APIM in internal VNet mode and an internal Kubernetes Service with an Azure load balancer. The Service sends traffic to a pod running the orders container. Keep the private endpoints reachable only by the intended callers and authenticate the APIM-to-backend hop as appropriate.
    • Locate the rejection. Both Front Door and APIM can return 403. Use Front Door WAF logs and request references to diagnose edge decisions, and APIM diagnostics or tracing for API policy decisions.
